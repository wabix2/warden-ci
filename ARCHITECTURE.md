# Warden CI Architecture

## Product boundary

Warden governs dependency risk introduced during AI-assisted development. It does not claim to prove that source code was generated by AI, and it does not replace a general SCA or SAST platform.

## Data flow

1. GitHub diff or IDE import is reduced to package names and ecosystem context.
2. The shared ecosystem provider resolves registry metadata.
3. `src/scan/riskSignals.ts` evaluates deterministic signals: existence, freshness, similarity, release history, publisher changes, and dependency-confusion proxies.
4. OSV malware advisories are checked where an ecosystem mapping exists.
5. `src/enforcement/policy.ts` evaluates annotations and produces the gate decision.
6. GitHub Check Runs, the HTTP package endpoint, and the VS Code extension render the result for their surface.

## Trust boundaries

- The registry and OSV are untrusted third-party inputs. Responses are parsed defensively and failures remain `unavailable`.
- IDE requests send package name and ecosystem only; source text is not sent by the package-check path.
- GitHub webhook requests require HMAC verification before the route accepts them. The current route is a signature-validation endpoint; GitHub Actions remains the canonical scan executor.
- Human sessions are separate from GitHub App installations. Installation ownership must be checked before accessing repository-scoped resources.

## Core modules

| Module | Responsibility | Evidence |
| --- | --- | --- |
| `src/scan/ecosystems/*` | extraction and registry metadata providers | provider tests and scan tests |
| `src/scan/riskSignals.ts` | deterministic package risk classification | `scripts/test-package-risk-signals.mjs` |
| `src/scan/index.ts` | diff scanning, annotations, policy handoff | package-risk and policy tests |
| `src/enforcement/policy.ts` | fail/warn/incomplete gate policy | `scripts/test-policy.mjs` |
| `src/auth/runAccess.ts` | session and installation authorization | `scripts/test-run-authorization.mjs` |
| `src/github/*` | webhook signature and GitHub integration helpers | webhook security tests |
| `ide-extension/src/*` | import extraction, debounce, cache, stale-scan suppression, diagnostics | extension test suite |

## Failure semantics

`not_found` means the registry answered and did not identify the package. `unavailable` means Warden could not determine the answer because of timeout, non-success response, or malformed metadata. Unavailable results become `registry-unavailable`, never `hallucinated` or safe.

## Current limitations

The repository contains deterministic local evidence, but deployed two-tenant authorization, production webhook processing/idempotency, provider-backed billing webhooks, and a real-world labeled benchmark corpus still require external infrastructure and credentials.
